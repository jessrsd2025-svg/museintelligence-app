## Abstract

MuseIntelligence ICD203 is a reading-room and governance app for the LIBERTAS // VERITAS // AEQUITAS system. It ingests source material, renders it as a browsable markdown wiki/index, and governs every claim in it with provenance, epistemic tags, and the 18-gate acceptance checklist. Nothing in the app is presented as settled fact unless a human has reviewed its source. This `AGENTS.md` gives coding and content agents direction for preserving the project's conceptual coherence, source integrity, and governance boundaries. It is a project instruction file, not a claim that the proposed system has been empirically validated.

## 3. Agent operating cycle: OODA

- **3.1 Observe:** capture the user request, source files, constraints, and signals; identify each source and its locator before treating it as evidence; separate direct observations from interpretations, generated analysis, and speculation; record uncertainty and missing context. In this repo, observation goes through the OBSERVE panel (§6) and ingestion (`museintelligence/ingest.py`, `museintelligence/provenance.py`).
- **3.2 Orient:** establish context, source quality, scope, and applicable policy; distinguish primary-source material from secondary reporting and model-generated synthesis; check for conflicting signals and alternate interpretations; select the mindset — **Spatial Mode** for topology, geometry, and coordinate validation; **Convergent Mode** for separating municipal legal baselines from secondary reporting (§7).
- **3.3 Decide:** select an action supported by the contract, verified evidence, and governing policy; make assumptions explicit; do not promote assumptions to facts; prefer reversible, scoped changes where uncertainty remains; escalate consequential ambiguity to a human. Decisions are gated by the AEQUITAS gates and the interdiction triggers (§4, §13; enforced by `museintelligence/gates.py` over `tools/aequitas_gate_linter.py`).
- **3.4 Act:** execute only within approved scope and authorized tool boundaries; verify the result against acceptance criteria; preserve source links, provenance, status transitions, and audit information; feed failures into calibration proposals; do not autonomously modify human-approved policy.

### TOOL-GH-01 — commit-anchor verifier

All GitHub reads in the app go through TOOL-GH-01, implemented in `tools/github_call.py` (`museintelligence/github.py` is the facade over it). The module exposes four operations:

- `pin_commit_sha(repo, ref)` — resolve a ref (tag or commit SHA) to its 40-hex commit SHA via the public GitHub API.
- `verify_ref(repo, ref, expected_sha)` — resolve a ref and, when an expected SHA is given, check the resolved SHA equals it.
- `fetch_bytes_at_sha(repo, sha, path)` — return the raw bytes of a file at a pinned commit SHA.
- `hash_bytes(data)` — return the SHA-256 hex digest of bytes.

Rules: fetch only at pinned 40-hex commit SHAs; never fetch from an unpinned ref; never trust a branch HEAD. Branch names (main, master, HEAD) are refused. The invariant is: **commit_sha is the anchor; branch names are not.** Reads use the public GitHub API without authentication; a `GITHUB_TOKEN` may be supplied to raise the rate limit, but it is never required. No credential or API key is stored in this repository.

## 7. Mindset selection

- **Spatial Mode:** validate topology and polygon coordinates; coordinates must use `[lon, lat]` ordering; enforce `navigation_suitability = 0` and `live_tracking: false`; do not equate geometric validity with navigational suitability.
- **Convergent Mode:** isolate municipal legal baselines from secondary reporting; preserve source class and evidentiary role; do not merge secondary reporting into a municipal legal baseline; if the resolution procedure is not specified, surface the ambiguity instead of inventing a rule.

## 8. Provenance & data rules

- Every source object carries a unique `source_id`, a stable `source_locator`, and a UTC `retrieval_timestamp`. A payload lacking any of the three is INCOMPLETE_PROVENANCE and fails the build (gate A1; deterministic routing to `quarantine.md`, gate E1).
- Canonicalization follows RFC 8785 before SHA-256 hashing (gate A2).
- External GitHub or Hugging Face references are pinned to immutable commit SHAs (TOOL-GH-01), never floating branch names (gate A3).
- Primary legal texts, secondary analyses, on-chain oracle hashes, and forum posts are stored as separate nodes rather than merged claims (gate A4).
- No claim is assigned VERIFIED_FACT without human review. Automated transitions from SOURCE_ASSERTION or CONTEXT_SIGNAL to VERIFIED_FACT are programmatically blocked (gate B1).
- Market and sentiment content is SENTIMENT_ONLY: it is never event evidence and never authorizes a graph mutation (gate B2).
- Generated analysis is labeled GENERATED_ANALYSIS and never substituted for verbatim source passages (gate B4).
- `graph_mutation_authorized` and `c2_mutation_authorized` default to false across all automated scripts (gate C1).
- Unverified relationships are restricted to RELATED_TO, MENTIONED_WITH, SUPPORTED_BY, and QUARANTINED_AS. Causal predicates (CONTROLS, OWNS, FINANCES, EXECUTES_C2) are absent as relationship types (gate C2).
- All GeoJSON layers enforce `[longitude, latitude]` coordinate order, `navigation_suitability: 0`, and `live_tracking: false` (gate C3).
- Unverified claims render strictly as RED_HOLLOW nodes; SOLID_MARKERS appear only where human-reviewed provenance exists (gate C4).
- No silent epistemic upgrades are performed. No merged claims. No causal edges are asserted.

## 9. Runtime model — open-source backend

- The app's AI backend is an open-source, open-weights model. No proprietary model serves as the app's engine. Google AI Studio is the build environment only; the model below is what the finished app runs.
- **Default model:** `Qwen/Qwen2.5-7B-Instruct` — an instruction-tuned 7B open-weights model (7.61B parameters, 131,072-token context, Apache License 2.0, ungated on Hugging Face), verified to exist on Hugging Face 2026-11-25. Its model card reports strengths in instruction following, understanding structured data, and generating structured outputs (JSON) — the app's core work of document reasoning, structured extraction, and checklist evaluation.
- **Selection criteria (for the default or any replacement):** an instruction-tuned open-weights model suited to document reasoning, structured extraction, and checklist evaluation; a license permitting the app's use (a permissive open license such as Apache 2.0); small enough to run in the app's hosting (7B class); ungated on Hugging Face.
- **Pinning (build time).** The model is served from Hugging Face and pinned to an immutable commit SHA — never a floating branch or tag — the same rule as TOOL-GH-01 / gate A3. At build time the SHA is resolved and pinned via the TOOL-GH-01 flow (`pin_commit_sha` to resolve the ref, `verify_ref` to check it), recorded in the app configuration, and the app loads weights only at that pinned SHA. A tag may be used only as the input to the pin step; the app never loads weights by a branch name or a tag. The pinned commit SHA for this build is: *to be pinned at build time*. No SHA is stated here — none was resolved at writing time, and inventing one would violate the provenance rules.
- **The model is a reasoning engine only.** It never assigns VERIFIED_FACT; its outputs are SOURCE_REPORTED / GENERATED_ANALYSIS until a human reviews them. The governance precedence hierarchy (§2) places model preference last: the model never overrides policy, this AGENTS.md, a gate, a task contract, or a dispatch. Implemented in `museintelligence/model.py` (lazy backend; loads only at a pinned 40-hex SHA, `local_files_only=True`; fails cleanly otherwise).

- **Scrape coverage:** the scrape covers public published posts only (577). Private and draft posts are not reachable through the public API and are not included. The scrape is a snapshot as of 2026-11-25T18:01:10Z; posts published after that are not covered until the scrape is re-run.

Those values are the author's published content, not values asserted by this repository. This AGENTS.md itself contains no 40-hex string and no floating branch reference.
